# Catalog — слой приложения

Оркестрация сценариев: читает домен через порты репозиториев, собирает контракт для витрины.

## Активные сценарии

| Сценарий | Назначение |
|----------|------------|
| `GetCatalogUseCase` | Публичное дерево каталога для SPA |

Расположение: `app/Application/Catalog/useCases/GetCatalogUseCase.php`.

## Что делает `GetCatalogUseCase`

1. Загружает активные категории в порядке сортировки.
2. Для каждой категории — упорядоченные позиции (товар или набор).
3. Подтягивает активные товары/наборы, теги, пищевую ценность, состав, изображения.
4. Собирает плоский JSON-контракт для фронта (деньги, nutrition, tags, ingredients, set lines).

Зависимости — только интерфейсы Domain: `CategoryRepository`, `CatalogItemRepository`, `TagRepository`.

## Админские мутации

Сейчас **не** проходят через Application Catalog. Операторские create/update/delete выполняет Filament напрямую через Eloquent-модели `PRD_*` (см. `filament.md`).

Целевое направление BC: вынести мутации в Command/Query сценарии Application — слой зарезервирован под это, но в репозитории пока один use case.

## DTO / Presenter / Ports

В кодовой базе могут присутствовать заготовки под админские команды, read-model для внешних интеграций и порты (хранение изображений, guards удаления). Пока они **не подключены** к Filament и не участвуют в runtime публичного API.
